# memo-capture スキル 保守ガイド

このドキュメントは **memo-capture スキルを更新・改善する保守者向け**。スキルを*使う*ためのものではない（使い方は `SKILL.md` が持つ）。設計の判断と「なぜそうしたか」を残し、将来の変更判断を助ける。

> 配置の意図: このファイルはリポジトリの `docs/` 配下に置き、**スキルディレクトリには含めない**。`make install` の symlink はスキルディレクトリ単位のため、`docs/` は `~/.claude/skills/` に露出せず、スキル実行時にロードされない。詳細は [writing-style の保守ガイド](./writing-style.md#なぜスキル外docsに置くか)を参照。

## 構造

```text
memo-capture/
└── SKILL.md            # 単一ファイル（保存先解決・カテゴリ判定・書式・検索手順）
```

補助ファイルを持たない。メモのテンプレートは 15 行程度で、[テンプレート管理方針](../template-management.md)の「200 行未満はコードブロックで直書き」に収まる。

## なぜこの設計か

### なぜ保存先を 4 段階で解決するか

メモリポジトリの置き場所は利用者ごとに違う。チームで同じスキルを共有しつつ、保存先だけを個人の環境に委ねる必要がある。

探索順（`MEMO_ROOT` → `~/.claude/memo-capture.yaml` → `git config memo.root` → `$GHQ_ROOT/github.com/*/memo`）は、`workspace-mcp` の所在解決（`mcp/pkg/workspace/resolve.go`）と同じ思想で揃えた。

- 環境変数を最優先 — 一時的な切り替え（テスト・別リポジトリへの記録）が最も軽い
- 個人設定ファイルを次に — 恒久設定の置き場。`~/.claude/` 配下なのでリポジトリを汚さない
- `git config memo.root` — プロジェクトごとに記録先を分ける需要への逃げ道
- 既定はグロブ探索 — `ghq` 利用者なら `$GHQ_ROOT/github.com/<user>/memo` に置くのが自然だが、`<user>` を特定する確実な手段がない。`github.com/*/memo` を探索し、**1 件に定まるときだけ**採用する。0 件・複数件はユーザーに確認する

未解決時にディレクトリを作らないのは、プロジェクト外への無断の書き込みを避けるため。

### なぜ既存メモを読み書きしないか

メモリポジトリは、別セッション・別マシン・他メンバーが並行して書き込む共有領域である。内容の読み取りや書き換えを既定で許すと、他者の成果物を無断で改変する経路になる。また、無関係なメモをコンテキストに読み込む分だけトークンを浪費する。

そこで既定の書き込みを「新規ファイルの作成」と「`INDEX.md` への 1 行追記」の 2 つに限定した。同名 slug が既にある場合も、内容を読まずにパスだけを提示して指示を仰ぐ。読み取りは `--find`（利用者が検索を明示的に指示した状態）でヒットしたファイルに限る。

### なぜカテゴリを 3 種に絞るか

`tips` / `ideas` / `refs` の 3 種のみ。分類が細かいほど記録時の判断コストが上がり、「メモを取ること自体が面倒」になって使われなくなる。3 種なら判定表 3 行で迷わない。粒度の細かい分類は frontmatter の `tags` が担う。

### なぜ 1 メモ 1 ファイル＋索引か

日付ジャーナル形式（`2026-09-06.md` に追記）と比較した結果、1 メモ 1 ファイルを選んだ。

- 話題単位で参照・共有でき、URL やパスで指し示せる
- 追記が「既存ファイルの書き換え」になるジャーナル形式は、上記の不干渉原則と衝突する
- `INDEX.md` があれば、全ファイルを開かずにタイトルと 1 行フックだけで一覧できる

### なぜ自動で発火させないか

description に「明示的に指示されたときだけ動作し、会話中に自動で提案はしない」と明記している。作業中に「メモに残しますか？」と割り込むと、本来のタスクの流れを断つ。メモを取るかどうかの判断は利用者に残す。

## 個人設定ファイルのサンプル

`~/.claude/memo-capture.yaml`（リポジトリにはコミットしない）:

```yaml
root: ~/ghq/github.com/takekazuomi/memo
```

## 更新の指針

- **保存先の探索順を変える** → SKILL.md の「保存先の解決」の表と `resolve_memo_root()` の両方を直す。`workspace-mcp` の `resolve.go` と乖離させる場合は理由をここに残す
- **カテゴリを増やす** → 「手順」の判定表に 1 行追加し、`INDEX.md` の雛形にも節を足す。増やす前に `tags` で足りないかを検討する
- **description の変更** → 自動ディスパッチの精度に直結する。発火語（「メモしておいて」「メモに残す」）と「自動で提案はしない」の但し書きを維持する
- 変更後は `npx markdownlint-cli2 "plugins/memo-capture/**/*.md"` で lint を通す（リポジトリ規約）
