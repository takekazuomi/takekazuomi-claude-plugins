マルチリポ・ワークスペース定義基盤の設計ドキュメントを追加

複数リポにまたがるコーディングエージェントのワークスペースを定義・共有する基盤の設計検討をまとめる。設計ドキュメント本体と、検討素材の模擬コード4本を追加。

設計の要点:
- 作業セット型（go.work 相当）と位置づけ。ビルド再現性は各リポの git tag・go.sum に委ね、マニフェストは担わない
- 3軸分離（Definition=共有・コミット／Placement=ghq でローカル解決／Overlay=非コミットの一時上書き）。Overlay は go.work の replace に対応し worktree で実現
- 検証2層（構造=JSON Schema／参照整合=Go）。ロール検証（repos[].role ∈ roles[].id）を中核に据える
- MCP を知識層として配置（6ツール）。ghq フラット配置でディレクトリツリーを捨てた帰結としての必須化
- revision は SHA 固定ではなく追跡ブランチの指定（既定はデフォルトブランチ、無指定も正常）
- 配布はバイナリ1つ（workspace-mcp）に集約し MCP/validate/--print-paths を兼用。GitHub Releases ＋ SessionStart フック ＋ ${CLAUDE_PLUGIN_DATA} キャッシュを主経路、go install をフォールバックとする
- docker・リモート HTTP はホスト FS 操作（ghq/worktree）と相容れず不適、と本文に明記

含まれるファイル:
- docs/workspace-platform-design.md  設計の結論（確認済み事実・推論・決定を区別）
- docs/workspace/workspace.yaml       マニフェストの例
- docs/workspace/workspace.schema.json 構造検証スキーマ
- docs/workspace/validate-workspace.go 参照整合検証
- docs/workspace/workspace-mcp.go      MCP サーバ

残課題:
- 模擬コードは設計ドキュメント先行のため一部未追従（validate_workspace ツール化、Overlay の override マージ＋worktree 解決、revision 警告の撤回、internal/workspace への分割、配布フック・リリース CI）
